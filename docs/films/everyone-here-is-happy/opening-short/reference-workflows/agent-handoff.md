# Agent review and extension contract

Start with [the package index](README.md), the current opening adaptation, and the relevant subject walkthrough. Do not use `superseded-full-story` as the production plan. The user scoped this short to the party, disappearance, Ethan's entry and first Playways arrival.

## Review in four separate layers

1. **Graph correctness:** input maps resolve, API and canvas connections agree, reference image reaches the model, all nodes have one intended purpose. Run `npm test`. This does not prove that Cloud has accepted the graph.
2. **Cloud compatibility:** import each canvas, confirm model/widgets/reference slots, submit one small pilot, record job ID and output. Do not label authentication rejection a successful workflow validation. The current package has no successful Cloud run.
3. **Visual quality:** compare the actual PNG with the anchor, prompt and continuity contract. Record identity, age, wardrobe, prop and geometry failures even when the service reports success.
4. **Creative selection:** record the chosen anchor and who approved it. Keep technical success, reviewer recommendation and project approval as different fields. No asset currently has that approval.

## Files to read and preserve

| File or directory | Responsibility |
|---|---|
| `workflows/ehih-opening/references/presets.json` | Authoring source for style, identity, casting proposals, preservation and view tasks |
| `scripts/build-opening-references.mjs` | Deterministic canvas/API/map generator; no Cloud calls |

| `scripts/run-opening-reference.mjs` | Explicit submit and collect; records provenance and handles image upload |
| `assets/ehih-opening/references/runs/<run-id>/` | Exact request snapshot, run record and original downloaded PNGs |
| `assets/ehih-opening/references/asset-register.json` | Selected reference pointers and approval status; never generated by the graph builder |
| `test/opening-references.test.ts` | Structural checks for graph/map parity and reference conditioning |

Paths are relative to the repository root. Do not write API keys or signed download URLs into these artifacts. Paths and hashes in run records are local provenance, not secrets or authentication.

## Review entry template

Add notes to the run record's `visual_review`, then update the asset register only when a selection is made:

```json
{
  "status": "reviewed_candidate",
  "reviewer": "agent-or-person-name",
  "notes": [
    "Identity: pass/fail with observed reason",
    "Age/anatomy: pass/fail with observed reason",
    "Wardrobe/prop state or room geometry: pass/fail with observed reason",
    "Recommended use and known limitations"
  ]
}
```

Do not copy example notes as if they were observations. A selected asset record should include `run_id`, actual output path, SHA-256, source anchor SHA-256 (for a derivative), view, model/settings and approval. Preserve rejected candidates and their reasons. Don't point a shot at `candidate-1.png` without also pinning its run directory and hash.

## Extending the package

For another camera angle or expression of the same design, add a named task to the subject's `views`, keeping the existing identity and preservation contract. The helper can run the new name immediately; rebuild if the default view changes. One reference image is supported by this package; adding multiple image inputs requires verified node schema, updated canvas slots and links, API inputs, role maps, tests and guides.

For a new actor, costume, token design, or a different room, create a new asset-family version. Do not silently overwrite an approved V01. Preserve the old presets and graph revision and identify affected shots. The film manifest's family IDs do not themselves identify image bytes.

For future shot composition, assign each supplied image a clear role: Ethan identity, Sarah identity, room geometry and any prop state. Compose a complete 16:9 keyframe for one editorial shot, review all elements together, then pass that approved keyframe to video. Do not animate a contact sheet or assume the still-reference graph produces a final shot. Character height, eyelines and contact with balls need joint review.

If text and image references cannot hold room geometry through necessary camera moves, propose a blockout/depth-control stage with a Cloud-supported node path. That is an extension, not a capability already implemented here.

## Completion checklist for the next live session

- Restore valid Cloud authentication without exposing the key.
- Import all six canvases and record compatibility; any UI repair must be reflected in API and builder output.
- Render one anchor for each package and review it. Keep casting and set design provisional until selected.
- Run at least one derivative using each actual selected anchor; compare for drift.
- Fill the asset register with real files, hashes and review/approval status.
- Hand approved references to the shot-composition stage with the exact workflow revision and unresolved limitations.

Do not batch every view before the first derivative passes review. A stable-looking portrait does not prove that all angles or the later video will preserve the character.
